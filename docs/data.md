# Data notes

## Sources (public, cited)

| Use | Public dataset | Fields used |
|---|---|---|
| SKU supply & backorder label | **Product backorders** — Kaggle `gowthammiryala/back-order-prediction-dataset` (https://www.kaggle.com/datasets/gowthammiryala/back-order-prediction-dataset) | `sku, national_inv, lead_time, in_transit_qty, forecast_3/6/9_month, sales_1/3/6/9_month, min_bank, potential_issue, pieces_past_due, perf_6/12_month_avg, local_bo_qty, deck_risk, oe_constraint, ppap_risk, stop_auto_buy, rev_stop, went_on_backorder` |
| Carrier transit timing & order value | **Brazilian E-Commerce Public Dataset by Olist** — Kaggle `olistbr/brazilian-ecommerce` (https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce), CC BY-NC-SA 4.0 | `olist_orders_dataset.csv`: purchase / approved / carrier / customer-delivered / estimated timestamps; `price` from `olist_order_items_dataset.csv` |

## What is committed

No real rows are committed. Both Kaggle sources need a Kaggle login, and no public mirror with a verifiably identical schema was found (Hugging Face search returned no backorder mirror, and the Olist mirrors found there were pre-processed/encoded variants). So the repo ships:

- `data/sample/backorder_sample_SYNTHETIC.csv` (500 rows) and `data/sample/olist_orders_sample_SYNTHETIC.csv` (300 rows), clearly labelled **SYNTHETIC**, generated by `scripts/generate_samples.py`.
- Loaders for the real files: `dop.data.load_backorders()` (handles the trailing summary row and the `-99` performance sentinel) and `dop.data.load_olist_orders()`.

To run on the real data, download from Kaggle into `data/raw/` (git-ignored) and run:

```bash
python -m dop.demo --backorder-csv data/raw/Kaggle_Training_Dataset_v2.csv \
                   --olist-csv data/raw/olist_orders_dataset.csv
```

(For Olist, merge `price` from `olist_order_items_dataset.csv` first, or the demo uses a default value of 100 per unit.) With real backorder data the hidden "true risk" for the simulated world falls back to the observed label (`went_on_backorder` → 1.0 / 0.05), and results must be labelled as coming from the public dataset.

## Synthetic generator design

- Backorder generator: lognormal demand, coverage, supplier performance (beta), categorical risk flags at plausible rates. `went_on_backorder` is drawn from a hidden logistic process (`latent_supply_risk`) that the model never sees directly. Base rate ~24% (the real data is far more imbalanced, ~0.7%).
- Olist-style generator: purchase → approval → carrier handover → delivery, with lognormal transit (p50 ≈ 7–8 days). Only the transit distribution and price are used.
- Order lines are drawn from the holdout SKUs, so the risk model never scores a SKU it was trained on.
